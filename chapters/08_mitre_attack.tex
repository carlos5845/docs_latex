\chapter{Análisis mediante MITRE ATT\&CK}\label{ch:mitre_attack}

\section{Fundamentación y Marco Teórico de MITRE ATT\&CK}

El marco MITRE ATT\&CK (\textit{Adversarial Tactics, Techniques, and Common Knowledge}) es una base de conocimiento global y estandarizada que clasifica el comportamiento táctico y técnico de actores maliciosos basándose en observaciones directas del mundo real.

A diferencia de modelos estrictamente lineales (como la \textit{Cyber Kill Chain}), MITRE ATT\&CK opera como una matriz multidimensional no secuencial. Su estructura permite comprender no solo qué fase atraviesa una intrusión, sino cómo actúa técnicamente el adversario en cada etapa mediante tres niveles jerárquicos:

\begin{itemize}
    \item \textbf{Tácticas (El Objetivo):} Representan el ``por qué'' de una acción; la meta operativa intermedia que persigue el atacante (ej. Acceso Inicial, Persistencia, Movimiento Lateral).
    \item \textbf{Técnicas (El Método):} Representan el ``cómo''; el método tecnológico o procedimental concreto empleado para alcanzar la táctica (ej. \textit{Spearphishing Link}, \textit{Valid Accounts}, \textit{Web Shell}).
    \item \textbf{Subtécnicas y Procedimientos:} La implementación específica y detallada documentada en el comportamiento de grupos de ciberamenazas conocidos (APTs) o variantes de malware.
\end{itemize}

En el contexto de la Universidad Nacional del Altiplano de Puno (UNAP), la matriz MITRE ATT\&CK Enterprise v14 se utiliza como el estándar técnico para:

\begin{enumerate}
    \item \textbf{Evaluación de cobertura:} Evaluar de forma sistemática la cobertura defensiva frente al perfil de intrusión universitario.
    \item \textbf{Mapeo de debilidades:} Mapear las debilidades de configuración detectadas en el relevamiento perimetral (\texttt{Server: nginx/1.16.1}, falta de directiva HSTS, cookies de sesión ASP.NET Core y ausencia de registros DMARC).
    \item \textbf{Telemetría y detección:} Definir reglas de telemetría y monitoreo (SIEM/EDR) basadas en registros reales de auditoría.
\end{enumerate}

A continuación, se detalla el contenido operativo de cada fase del procedimiento:

\begin{enumerate}
    \item \textbf{Selección de Amenazas Prioritarias:} Se define el perfil del adversario que ataca al sector educación superior peruano: actores motivados por robo masivo de identidades/credenciales, grupos de \textit{ransomware} que extorsionan con la paralización de sistemas de matrícula o planillas, y atacantes oportunistas que explotan software público desactualizado.
    \item \textbf{Identificación de Tácticas Relevantes:} Se seleccionan las 8 fases críticas de intrusión: Reconocimiento $\rightarrow$ Acceso Inicial $\rightarrow$ Ejecución $\rightarrow$ Persistencia $\rightarrow$ Escalada de Privilegios $\rightarrow$ Descubrimiento $\rightarrow$ Movimiento Lateral $\rightarrow$ Exfiltración.
    \item \textbf{Mapeo de Técnicas Específicas:} Se asocian técnicas de la matriz ATT\&CK a los componentes descubiertos en la UNAP (portales web, APIs de matrícula, servidores Nginx/Kestrel, controladores de dominio y puestos de trabajo).
    \item \textbf{Evaluación de Brechas de Cobertura (\textit{Gap Analysis}):} Se contrasta la capacidad de detección actual de la OTI frente a cada técnica, identificando puntos ciegos (por ejemplo: falta de inspección en terminales PowerShell, logs web que no se correlacionan o ausencia de alertas por uso anómalo de credenciales válidas).
    \item \textbf{Creación de Reglas de Detección:} Se diseñan reglas específicas en formato de eventos de Windows (Sysmon/Event ID), directivas de inspección para Linux auditd y firmas de correlación en el SIEM institucional (Wazuh).
    \item \textbf{Definición de Respuestas:} Se establecen acciones inmediatas para mitigar o interrumpir cada técnica cuando sea alertada por el centro de operaciones de seguridad.
\end{enumerate}

\section{Especificación de Reglas de Detección e Implementación}

Para asegurar que el plan proporcione herramientas técnicas directamente aplicables en la OTI, se definen tres reglas de detección estandarizadas listas para ser integradas en el entorno defensivo:

\subsection*{Regla 1: Detección de Web Shells en Servidores Web UNAP (Wazuh FIM / Sysmon)}
Apunta a neutralizar la técnica T1505.003 en directorios de aplicaciones web (\texttt{matricula}, \texttt{campus}, \texttt{admision}):

\begin{cmdbox}{Regla Wazuh FIM: Deteccion Web Shell (T1505.003)}
<!-- Regla Wazuh / Ossec para detectar persistencia en servidores web -->
<group name="syscheck,web_attack,">
  <rule id="100100" level="12">
    <if_sid>550</if_sid>
    <field name="file">/var/www/|/usr/share/nginx/html/|C:\inetpub\wwwroot\</field>
    <match regex="(?i)\.(php|aspx|asp|jsp|sh|py)$">file</match>
    <description>ALERTA CRITICA: Creacion o modificacion de archivo ejecutable en directorio web publico (Posible Web Shell - T1505.003)</description>
    <mitre>
      <id>T1505.003</id>
    </mitre>
  </rule>
</group>
\end{cmdbox}

\subsection*{Regla 3: Detección de Anomalías de Concurrencia y Fuerza Bruta en Nginx (T1110 / T1078)}
Configurada sobre los logs de acceso de \texttt{/var/log/nginx/access.log} para mitigar ataques dirigidos contra el endpoint \texttt{/matricula/alumno/horario} o la interfaz de login:

\begin{cmdbox}{Regla Sigma: Deteccion Fuerza Bruta en Nginx}
# Regla de deteccion en SIEM / Sigma Rule
title: Intentos Masivos de Fuerza Bruta / Credential Stuffing en Portal UNAP
status: experimental
description: Detecta mas de 15 respuestas HTTP 401 o 403 en menos de 1 minuto desde una misma IP contra los endpoints de autenticacion.
logsource:
  service: nginx_access
detection:
  selection:
    uri|contains:
      - '/matricula/login'
      - '/auth/login'
      - '/campus/login'
    status:
      - 401
      - 403
  timeframe: 1m
  condition: selection | count() > 15
tags:
  - attack.credential_access
  - attack.t1110.001
level: high
\end{cmdbox}

\subsubsection*{B. Escenario de Prueba 1: Detección de Persistencia vía Web Shell (T1505.003)}

\begin{itemize}
    \item \textbf{Técnica MITRE:} \texttt{T1505.003 - Server Software Component: Web Shell}
    \item \textbf{Táctica:} Persistencia (\texttt{TA0003})
    \item \textbf{Vector Modelado:} Un adversario aprovecha una debilidad de carga de archivos en el portal académico para depositar un script ejecutable (\texttt{.aspx}, \texttt{.php}) en directorios estáticos de la aplicación.
\end{itemize}

\paragraph{1. Configuración del Agente (\texttt{ossec.conf}):}
Se instruye al agente a monitorear en tiempo real los directorios raíz donde opera la aplicación de matrícula:

\begin{cmdbox}{Configuracion FIM en /var/ossec/etc/ossec.conf}
<!-- Configuracion FIM en /var/ossec/etc/ossec.conf -->
<syscheck>
  <disabled>no</disabled>
  <frequency>300</frequency>
  <scan_on_start>yes</scan_on_start>
  
  <!-- Vigilancia en tiempo real sobre rutas de contenido web -->
  <directories check_all="yes" realtime="yes" report_changes="yes">/var/www/matricula/uploads</directories>
</syscheck>
\end{cmdbox}

\paragraph{2. Regla de Correlación Específica (\texttt{local\_rules.xml}):}
Se implementa una regla personalizada para elevar el nivel de severidad cuando se detecte la creación de archivos con extensiones ejecutables dentro de rutas web públicas:

\begin{cmdbox}{Regla Wazuh Manager: /var/ossec/etc/rules/local\_rules.xml}
<!-- Regla añadida en el Wazuh Manager: /var/ossec/etc/rules/local_rules.xml -->
<group name="syscheck,unap_web_security,">
  <rule id="100301" level="12">
    <if_sid>550</if_sid> <!-- Evento base: Archivo modificado/creado -->
    <field name="file">/var/www/matricula/uploads/</field>
    <match regex="(?i)\.(aspx|php|jsp|sh|py|pl|cgi)$">file</match>
    <description>ALERTA CRITICA UNAP: Creacion de archivo ejecutable en directorio web publico (Posible Web Shell)</description>
    <mitre>
      <id>T1505.003</id>
      <tactic>Persistence</tactic>
    </mitre>
  </rule>
</group>
\end{cmdbox}

\subsubsection*{C. Escenario de Prueba 2: Detección de Ataque de Fuerza Bruta Web (T1110.001)}

\begin{itemize}
    \item \textbf{Técnica MITRE:} \texttt{T1110.001 - Brute Force: Password Guessing}
    \item \textbf{Táctica:} Acceso a Credenciales (\texttt{TA0006})
    \item \textbf{Vector Modelado:} Un adversario ejecuta un script automatizado para adivinar contraseñas de docentes en el endpoint de autenticación de la intranet de matrícula.
\end{itemize}

\paragraph{1. Configuración de Ingesta de Logs de Nginx:}
El archivo \texttt{/var/ossec/etc/ossec.conf} recolecta los accesos generados por el proxy inverso:

\begin{cmdbox}{Configuracion Ingesta de Logs Nginx (/var/ossec/etc/ossec.conf)}
<localfile>
  <log_format>apache</log_format> <!-- Compatible con el formato Combined de Nginx -->
  <location>/var/log/nginx/access.log</location>
</localfile>
\end{cmdbox}

\paragraph{2. Regla de Umbral y Frecuencia en Wazuh:}
Se establece una regla de umbral compuesta que monitorea respuestas HTTP 401 Unauthorized o 403 Forbidden acumuladas en ventanas breves de tiempo:

\begin{cmdbox}{Regla Compuesta en /var/ossec/etc/rules/local\_rules.xml}
<group name="web,accesslog,unap_auth,">
  <!-- Regla base: Respuesta de acceso denegado -->
  <rule id="100310" level="5">
    <if_sid>31101</if_sid>
    <url>/matricula/login|/auth/login</url>
    <id>401|403</id>
    <description>Fallo de autenticacion en portal de matricula UNAP</description>
  </rule>

  <!-- Regla compuesta: 8 fallos en menos de 60 segundos desde la misma IP -->
  <rule id="100311" level="10" frequency="8" timeframe="60">
    <if_matched_sid>100310</if_matched_sid>
    <same_source_ip />
    <description>ALERTA ALTA: Posible ataque de fuerza bruta / Password Spraying contra portal UNAP</description>
    <mitre>
      <id>T1110.001</id>
      <tactic>Credential Access</tactic>
    </mitre>
  </rule>
</group>
\end{cmdbox}

\subsubsection*{D. Conclusiones de la Validación Técnica}

\begin{itemize}
    \item \textbf{Eficacia de Mapeo:} Se constata que la implementación de reglas personalizadas en Wazuh permite traducir de forma directa las técnicas abstractas de MITRE ATT\&CK (\texttt{T1505.003} y \texttt{T1110.001}) en alertas operativas con evidencia pericial (rutas, hashes SHA-256 e IPs de origen).
    \item \textbf{Respuesta Automatizada (\textit{Active Response}):} La infraestructura evaluada queda preparada para disparar acciones defensivas en caliente: ante la regla \texttt{100311}, el agente puede invocar de forma automática un script que añada la dirección IP a las tablas de bloqueo dinámico (\texttt{iptables} o \texttt{firewall-drop}) durante 30 minutos, mitigando el vector de intrusión antes de que comprometa credenciales válidas.
\end{itemize}

\section{Acciones de Respuesta y Remediación por Táctica}

Para cerrar el ciclo operativo, el equipo de respuesta a incidentes (CSIRT-UNAP) ejecutará los siguientes procedimientos operativos estándar ante la activación de alertas mapeadas en ATT\&CK:

\begin{itemize}
    \item \textbf{Ante alertas de Reconocimiento / Acceso Inicial (T1566 / T1078):}
    \begin{itemize}
        \item Revocación inmediata de tokens de sesión activos (\texttt{.AspNetCore.Cookies}) y forzado de reseteo de credenciales en el directorio unificado.
        \item Aislamiento preventivo de la IP de origen en las tablas dinámicas del Firewall perimetral (\textit{Drop rules} por 72 horas).
    \end{itemize}

    \item \textbf{Ante alertas de Ejecución / Persistencia (T1059 / T1505):}
    \begin{itemize}
        \item Aislamiento lógico de la estación o servidor web mediante corte de red en switch/VLAN (manteniendo la alimentación eléctrica para análisis forense de memoria volátil).
        \item Extracción de artefactos, eliminación de archivos no autorizados y restauración del contenedor/servicio web a partir de la imagen dorada (\textit{Golden Image}) del repositorio Git institucional.
    \end{itemize}

    \item \textbf{Ante alertas de Descubrimiento / Movimiento Lateral (T1046 / T1021):}
    \begin{itemize}
        \item Deshabilitación temporal de cuentas de servicio o usuarios locales de administración compartidos.
        \item Verificación y bloqueo de tráfico este-oeste entre subredes de facultades y el segmento del Data Center de la OTI.
    \end{itemize}
\end{itemize}
